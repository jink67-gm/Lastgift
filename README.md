# 자정의 마지막 선물

초등학교 3~6학년용 2~4인 협동 3D 브라우저 게임. 기획 기준은 `LAST_GIFT_SPEC.md` 버전 2.2. 작업 기록과 다음 작업 목록은 `DEVLOG.md`.

## 지금 할 수 있는 것

- 눈 광장에서 요정 1명을 WASD 또는 방향키로 움직인다. 위·아래·좌·우는 화면 기준이다.
- 한글 입력 상태에서도 동작한다(물리 키 위치 `event.code`로 판정).
- 썰매·산타·트리·집·벤치·가로등에 막히고 벽을 따라 미끄러진다. 광장 밖으로 나가지 않는다.
- 태블릿: 화면 왼쪽 아무 곳에 손가락을 대고 끌면 스틱, 오른쪽 아래 둥근 버튼이 행동. 두 손가락을 동시에 쓸 수 있다.
- E 키 또는 행동 버튼으로 가까운 선물(노란 고리 표시)을 들고, 다시 누르면 앞에 내려놓는다.
  무거운 재봉틀 상자는 혼자 들 수 없다(두 손 그림이 뜬다).
- 지금 누르면 일어날 일은 글 대신 그림으로 보여 준다(키보드: 화면 위 [E]+그림, 터치: 행동 버튼 안 그림).
- 왼쪽 위 팀 시계가 30:00부터 줄어든다. 방장 탭이 숨으면 팀 전체가 멈추고, 돌아오면 3초 카운트다운 뒤 다시 흐른다.
- 0초가 되면 시간 초과 화면 → 「다시 하기」로 같은 장 시작(저장한 시간 복구). 새로고침해도 체크포인트에서 이어 한다.
- 저장하지 못하면 시계 옆에 저장 실패 그림이 뜬다(게임은 계속된다).

## 여러 기기 연결 (명세서 §8, `src/net/`)

- **처음 소개(시그널링)만 Firebase**, 게임 데이터는 **WebRTC로 기기끼리 직접**. 같은 와이파이라면 데이터가 교실 와이파이 안에서만 오간다.
- 방장 기기가 운반 규칙과 팀 시계를 혼자 계산하고(약 15Hz로 화면 상태를 보낸다), 참가자는 입력만 보낸다(30Hz).
  채널 둘: `state`(순서·재전송 없음: 이동 입력·화면 상태), `mission`(순서·신뢰: 행동·재시도, runId·epoch·playerId·eventId 포함).
  방장은 이 연결에 배정한 자리로 다시 확인하고, 재전송·지난 epoch·다른 방 이벤트를 거른다.
- 자리: 방장 p0, 참가자는 들어온 순서대로 p1~p3(최대 4명). 같은 기기(같은 익명 uid)로 다시 들어오면 같은 자리.
  시작한 뒤에는 처음 보는 기기를 받지 않는다.
- 참가자 소식이 2.5초 끊기면 나간 것으로 본다: 손잡이를 놓고(재봉틀은 그 자리), 한 명만 남으면 팀 일시중지.
  돌아오면 같은 자리로 복귀하고 모두에게 같은 재개 시각(3초 뒤)을 알린다. 방장 탭이 숨으면 팀 전체 일시중지.
- 방장이 나가면 자동 승계는 없다. 같은 기기에서 다시 열면 같은 방 코드·자리로 다시 열리고, 참가자는 자동으로 재접속을 요청한다.
- **모든 장 공통(`src/net/team.ts`, STEP 07)**: 방장은 그 장의 규칙(`src/core/*`)을 그대로 돌리고 장 상태 + 팀 시도 상태를 보낸다.
  참가자는 같은 장 화면 코드로 받은 상태를 그린다(`session/mirrorRun.ts`: 시계·일시중지·다시 하기 표시). 집기·완료 같은 장 사건은
  `mission` 채널로 보내 소리·연출을 시작하고, 사건을 놓쳐도 장 상태(완료·배달)로 끝 장면을 시작한다.
  - 장이 끝나면 방장 페이지만 다시 읽히고(이야기 모드), 참가자는 방장이 새 장을 연 것을 보고 페이지를 다시 연다(시도가 바뀌어도: 「처음부터」).
  - 방(방 코드·자리·시작 여부)은 방장 기기에, 장 기록은 방마다 따로(`net-<코드>`) 저장된다. 다른 방의 기록·사건과 섞이지 않는다.
  - 끊긴 요정은 멈추고 들던 것(선물·공·전선·발전기 손잡이·스노글로브·재봉틀 손잡이)을 그 자리에 놓는다(`core/presence.ts`).
  - 장 장면을 만드느라 기기가 몇 초 멈출 수 있어, 들어온 직후·장을 연 직후 30초는 조용해도 끊긴 것으로 보지 않는다(느린 기기는 3장을 15초 넘게 읽었다).
    참가자는 연결을 맺는 중(20초까지)에는 다시 접속을 요청하지 않는다(요청마다 방장이 처음부터 다시 맺어 4기기에서 영영 못 붙었다).
  - 2장 개발 주소(`?chapter=2&host`)는 예전 2장 전용 코드(`game/chapter2Net.ts`)를 그대로 쓴다(이야기 모드 2장은 공통 층).

### Firebase 설정 (한 번)

이 게임 전용 Firebase 프로젝트(`lastgift-cbaac`)를 쓴다. 무료 요금제(Spark)로 충분하다(처음 소개 신호만 잠깐 주고받는다).

1. **Authentication → 시작하기 → 로그인 방법: 익명 사용 설정.**
2. **Authentication → 설정 → 승인된 도메인**에 게임을 올릴 주소(`jink67-gm.github.io`)를 추가한다(`localhost`는 기본으로 있다).
3. **Realtime Database → 규칙**: 이 저장소의 `database.rules.json` 내용을 붙여 넣고 「게시」.
4. 설정값: 저장소에는 키를 넣지 않는다. `.env.example`을 `.env.local`로 복사해 값을 채운다(`.env.local`은 Git에 올라가지 않는다).
   배포(GitHub Pages)할 때는 GitHub 저장소의 Actions 비밀 값으로 넣어 빌드한다(아래 「배포」).

값이 없으면 「방 만들기」·「참가」가 "설정이 아직 없어요"로 멈추고, 「한 기기에서 둘이」는 그대로 된다.
방 정보는 3시간 뒤 만료된다. 실명은 쓰지 않는다(자동 요정 별명).

### 배포 (GitHub Pages)

`main`에 올리면 `.github/workflows/pages.yml`이 시험 → 빌드 → 배포한다. 주소: https://jink67-gm.github.io/Lastgift/

처음 한 번:
1. GitHub 저장소 → Settings → Pages → Build and deployment → Source: **GitHub Actions**
2. Settings → Secrets and variables → Actions → New repository secret으로 다섯 개를 넣는다(값은 `.env.local`과 같다):
   `VITE_FIREBASE_API_KEY`, `VITE_FIREBASE_AUTH_DOMAIN`, `VITE_FIREBASE_DATABASE_URL`, `VITE_FIREBASE_PROJECT_ID`, `VITE_FIREBASE_APP_ID`
3. Actions 탭 → 「Pages 배포」 → Run workflow (또는 main에 다시 올리기)

비밀 값이 빠져 있으면 배포 전에 멈추고 빠진 이름을 알려 준다.

### 키 도용 막기

Firebase 웹 설정값(apiKey 포함)은 빌드된 게임 파일에 들어가 **브라우저에서 누구나 볼 수 있는 공개 정보**다.
`.env.local`로 빼면 저장소 코드에는 남지 않지만, 배포된 게임에서는 여전히 보인다. 그래서 아래로 막는다.

| 방법 | 막는 것 | 어디서 |
|---|---|---|
| 보안 규칙(`database.rules.json`) | 키를 가져가도 `lastgiftRooms`의 정해진 모양 말고는 읽고 쓸 수 없다(크기 제한·3시간 만료·남의 신호 읽기 금지·그 밖의 경로 모두 거부) | Firebase 콘솔 → Realtime Database → 규칙 |
| API 키 사용처 제한 | 다른 웹사이트에서 이 키로 로그인하지 못하게 한다 | Google Cloud 콘솔 → API 및 서비스 → 사용자 인증 정보 → "Browser key (auto created by Firebase)" |
| 무료 요금제 유지 | 누가 마구 써도 요금이 나오지 않고 한도에서 멈춘다 | 결제 계정을 연결하지 않는다 |
| App Check(선택) | 우리 게임 페이지에서 온 요청만 받는다(reCAPTCHA) | 배포 뒤 함께 설정 |

API 키 사용처 제한 값:
- 애플리케이션 제한사항 → **웹사이트**: `https://jink67-gm.github.io/*`, `http://localhost:5173/*`, `http://localhost:4173/*`
- API 제한사항 → **키 제한**: `Identity Toolkit API`, `Token Service API` (Realtime Database는 이 키를 쓰지 않는다)

## 2장 재봉틀 운반 규칙 (명세서 §5, §3.2, `src/core/sewing.ts`)

- 손잡이 2개. 둘 다 잡으면 들린다. 같은 방향으로 밀면 이동, 한쪽이 멈추면 멈춘 손잡이를 축으로 돈다(혼자 끌고 갈 수 없다).
- 무게를 든 사람만 체력이 준다(가득 찬 상태로 약 28.6초). 25% 이하면 손잡이 옆에 교대 표시, 0이면 그 자리에 내려놓는다.
- 쉬던 요정이 잡힌 손잡이에서 행동하면 상자는 들린 채 손잡이 주인만 바뀐다(한 순간에 손잡이 하나당 한 번).
- 덧문은 밀면 4초 열렸다 닫힌다. 걸쇠를 걸거나, 행동 버튼을 누르고 있거나, 문틀에 사람·상자가 있으면 닫히지 않는다.
- 2인 팀: 문 앞 받침대에 내려놓고 → 한 명이 걸쇠를 걸고 → 다시 함께 든다. 긴 쪽을 틀어야 문을 지난다.
- 공간: 팀원 전원과 재봉틀이 통로 끝을 넘으면 작업실을 **한 번만** 확정한다(전환 번호 기록). 먼저 넘은 요정은
  작은 대기 구역까지만 갈 수 있다. 같은 장 안의 이동이므로 체크포인트는 저장하지 않는다.
- 작업대에 긴 쪽을 맞춰 내려놓으면 2장 완료(기억 2) → 이때 다음 장 체크포인트를 저장한다.

## 팀 시계 규칙 (명세서 §7, `src/core/run.ts`)

- 방장만 계산한다. 모든 명령은 방장이 받은 시각으로 판정하고, 참가자 기기가 적은 시각은 쓰지 않는다.
- 장 최초 진입: `savedRemainingMs = max(남은 시간, 장 바닥값)`을 한 번만 저장하고 보탠 양을 `timeAssistMs`에 기록한다.
  바닥값은 0~6장 순서로 3·4·5·5·5·2·3분. 체크포인트에서 이어 하거나 재시도할 때는 다시 보정하지 않는다.
- 장 완료·기억·다음 장 최초 체크포인트를 한 번의 저장으로 확정한다.
- 가벼운 실수: 시계·체크포인트 그대로, 장마다 정한 임시 진행만 푼다(4장은 스위치만).
- 마감과 같은 시각의 전달은 승리, 1ms라도 늦으면 시간 초과. 엔딩은 한 번만.
- 같은 이벤트 재전송(eventId), 지난 시도의 이벤트(epoch), 다른 방의 이벤트(runId)는 거른다.
- 주소 끝에 `?test`를 붙이면 자동 검사용 창구(`window.__lastgift`)가 열린다.
  0장 시험 모드는 `&prologue`, 1장 시험 모드는 `&story`가 있을 때만 앞 연출을 튼다. 동작 확인용: `&zoom=배율`(1P 가까이), `&slow=배율`(느리게, 1보다 작으면 빠르게).
